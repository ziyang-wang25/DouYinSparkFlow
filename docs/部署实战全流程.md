## 一、工作原理

该项目通过 **GitHub Actions 定时任务** + **Playwright 无头浏览器** 实现：

1. 每天按 cron 设定的时间触发工作流（GitHub 服务器执行）
2. Playwright 启动 Chromium，注入登录 cookies 打开 `https://www.douyin.com/chat`
3. 等待会话列表加载，通过监听 `aweme/v1/web/im/user/info` 接口收集好友信息（昵称→备注名映射）
4. 在会话列表中逐个匹配配置的目标好友，点击进入聊天窗口
5. 按 `MESSAGE_TEMPLATE` 拼装消息（`[API]` 占位符替换为一言/OpenAI 内容），模拟输入并回车发送
6. 全部发送完成后保存日志并上传为 GitHub Actions 产物（artifact）

```
cron (12:35 北京) → workflow_dispatch/schedule → 安装依赖+浏览器 → 注入cookies
→ 打开 www.douyin.com/chat → 等待 userIDDict 就绪 → 滚动匹配目标好友
→ 逐条发送消息 → 上传日志
```

## 四、部署步骤

### 1. Fork 上游仓库

1. 打开 https://github.com/2061360308/DouYinSparkFlow → 右上角 **Fork** 到自己的账号
2. Fork 后仓库包含 `main` / `dev` / `api` 分支（dev 分支需手动确认存在）

### 2. 创建 GitHub Environment

```
仓库 → Settings → Environments → New environment
名称：user-data
```

无需配置 protection rules，直接创建即可。

### 3. 配置 Variables

在 `user-data` 环境下添加以下变量（值参考 [配置项说明](#五配置项说明)）：

| 变量名 | 必填 | 说明 |
|--------|------|------|
| `TASKS` | ✅ | 任务 JSON：发送账号 + 目标好友列表 |
| `MESSAGE_TEMPLATE` | ✅ | 消息模板（`[API]` 为动态内容占位符） |
| `LOG_LEVEL` | 可选 | 日志级别，默认 `Info` |
| `BROWSER_TIMEOUT` | 可选 | 浏览器操作超时毫秒数，默认 `120000` |
| `TASK_RETRY_TIMES` | 可选 | 失败重试次数 |
| `MAX_EMPTY_SCROLLS` | 可选 | 列表滚动到底判断次数 |
| `SEND_DELAY` | 可选 | 发送间隔秒数 |
| `OPENAI_API_KEY` | 可选 | 配置后 `[API]` 走 OpenAI 生成（否则用一言） |

`TASKS` 示例：

```json
[
  {
    "username": "雨抚床鈴",
    "unique_id": "39751151103",
    "targets": ["无敌火影大王", "不会正手快带", "睡觉吧孩子睡觉吧", "佛系陈", "Aurora²⁰⁷⁷"]
  }
]
```

> `unique_id` 是唯一标识，**必须与 Secret 名称后缀一致**（`COOKIES_39751151103`）。`username` 仅为日志显示用。

### 4. 配置 Secret（cookies）

**这是本部署最关键的一步 —— 必须使用 `www.douyin.com` 的登录 cookies！**

#### 4.1 导出 cookies

1. 用 Chrome/Edge 打开 **https://www.douyin.com/chat**，确认已登录（能看到左侧聊天列表）
2. 刷新一次页面，确保会话为最新状态
3. 使用 **Cookie-Editor**（或 EditThisCookie）扩展 → **Export → JSON**
4. 复制全部 JSON 内容

> ✅ 正确的 cookie 集合必须包含（缺了会显示登录页）：
> - `__ac_signature`（www.douyin.com 域，反爬/设备指纹关键项）
> - `__ac_nonce`
> - `fpk1` / `fpk2`
> - `device_web_cpu_core` / `device_web_memory_size`
> - `sessionid` / `sid_guard` / `sid_tt` / `uid_tt` / `ttwid`（登录会话）
>
> ❌ 从 `creator.douyin.com` 导出的 cookies 对网页聊天版无效（打开 `/chat` 会停在"扫码登录"页）。

#### 4.2 清洗并上传 Secret

上传前必须清洗 cookies（否则 Playwright `add_cookies` 会报错）：

```python
# 清洗规则
# 1. 删除 name 为空的条目（导出工具会带一条 name="" value="douyin.com" 的脏数据）
# 2. expirationDate → expires（整数秒）
# 3. 删除 sameSite 字段（"no_restriction" 不是 Playwright 合法值；config.py 也会 pop）
# 4. 仅保留 name / value / domain / path / expires / httpOnly / secure
```

上传方式（推荐用 API 脚本，Token 需 `repo` 权限，`pynacl` 用于 Secret 加密）：

```python
# update_secret.py 核心逻辑（已按本项目实际验证）
import json, os, base64, requests
from nacl import encoding, public

owner, repo, env_name = "ziyang-wang25", "DouYinSparkFlow", "user-data"
secret_name = "COOKIES_39751151103"
token = os.environ["GH_TOKEN"]

cookies = json.load(open("cookies_clean.json", encoding="utf-8"))
secret_value = json.dumps(cookies)

# 1. 获取环境的公钥（用于加密 Secret）
h = {"Authorization": f"Bearer {token}", "Accept": "application/vnd.github+json"}
pub = requests.get(f"https://api.github.com/repos/{owner}/{repo}/environments/{env_name}/secrets/public-key", headers=h).json()
# 注意：key_id 用 pub["key_id"]，加密用 pub["key"]

# 2. 用 pynacl 加密
pub_key = public.PublicKey(pub["key"].encode("utf-8"), encoding.Base64Encoder())
sealed = public.SealedBox(pub_key).encrypt(secret_value.encode("utf-8"))
encrypted = base64.b64encode(sealed).decode("utf-8")

# 3. 上传
body = {"encrypted_value": encrypted, "key_id": pub["key_id"]}
r = requests.put(f"https://api.github.com/repos/{owner}/{repo}/environments/{env_name}/secrets/{secret_name}", headers=h, json=body)
assert r.status_code == 204, r.text
print("Secret 更新成功")
```

> ⚠️ **常见坑**：`key_id` 必须取 `pub["key_id"]`，`pub["key"]` 是加密公钥本体，两者不能混用（混用会导致 Secret 无法解密，运行时解析失败）。

### 5. 推送 dev 分支代码

本地克隆仓库并推送 dev 分支（Token 需 `repo` + `workflow` 权限，否则 push `.github/workflows/` 会 403）：

```bash
git clone https://github.com/ziyang-wang25/DouYinSparkFlow.git
cd DouYinSparkFlow
git checkout dev
# （如需修改代码，提交后）
git push origin dev
```

> 若本地推送遇 SSL 报错，可临时使用：`git -c http.sslVerify=false push origin dev`

### 6. 启用 dev 分支工作流

Fork 仓库的新工作流默认是 `disabled_fork` 状态：

```
仓库 → Actions → 左侧找到「【dev（测试）分支】DouYin Spark Flow Schedule Run」
→ 点开 → Enable workflow（启用）
```

启用后即可手动触发：

```
Actions → 选中该工作流 → Run workflow → 分支选 dev → Run
```

### 7. 验证发送

手动触发一次，等待运行结束（约 2~3 分钟），然后：

1. 在 Actions 运行页下载 `run-logs` artifact，打开 `app.log` 确认：
   - `会话列表容器已加载`
   - `匹配到目标好友: xxx`（每个目标一条）
   - `给好友 xxx 发送消息完成`
   - 无 `仍有以下好友未找到` 警告
2. 在抖音 App/网页上确认接收方实际收到消息

## 五、配置项说明

### 定时触发（cron）

`schedule_dev.yml`：

```yaml
on:
  schedule:
    - cron: "35 4 * * *"   # UTC 04:35 = 北京时间 12:35
  workflow_dispatch: {}
```

> - GitHub Actions 的 cron 使用 **UTC 时区**，北京时间 = UTC + 8
> - fork 仓库的 `schedule` 事件**可以正常触发**（本项目已验证）
> - 调度可能有 5~15 分钟延迟

### 消息模板（MESSAGE_TEMPLATE）

```
[盖瑞]今日火花[加一]\n—— [右边] 每日一言 [左边] ——\n[API]
```

- `\n` 表示换行（字面反斜杠+n，代码按此拆分逐行输入）
- `[盖瑞]`、`[加一]`、`[右边]`、`[左边]` 是抖音表情代码，会原样发送
- `[API]` 占位符：未配置 `OPENAI_API_KEY` 时替换为一言（hitokoto）随机语录；配置后走 OpenAI

### 日志级别

`LOG_LEVEL=Info`：能看到关键流程；`Debug` 可看到遍历的每个会话、消息内容等详细日志。

## 八、常见问题排查

### Q1：页面停在"扫码登录"，永远等不到会话列表

**原因**：cookies 无效 —— 不是 www.douyin.com 的登录态（常见于从 creator.douyin.com 导出、或缺少 `__ac_signature`）。

**排查**：运行日志中若出现 `页面正文: '抖音聊天 | 登录后免费畅享高清视频 | 扫码登录 ...'` 即为本问题。

**解决**：按 [4.1 导出 cookies](#41-导出-cookies) 重新导出完整的 www.douyin.com cookies 并重新上传 Secret。

### Q2：5 个目标全部"未找到"

**原因**：`userIDDict`（好友信息映射）未就绪就开始了匹配。监听接口 `aweme/v1/web/im/user/info` 在页面 `domcontentloaded` 之后才返回，匹配数据为空导致只能退化为"会话标题直接等于昵称"比较，失败率高。

**解决**（已在 dev 分支代码中修复）：遍历前轮询等待 `userIDDict` 非空（最长 60 秒），日志输出 `好友信息接口数据就绪: N 条`。

### Q3：打开聊天页每次卡 120 秒

**原因**：`page.goto` 默认等待页面 `load` 事件，而抖音页面存在长连接/埋点资源导致 `load` 迟迟不触发。

**解决**（已在 dev 分支代码中修复）：goto 增加 `wait_until="domcontentloaded"`，页面 DOM 就绪即返回，配合上一条的 `userIDDict` 等待保证匹配数据完整。

### Q4：Secret 上传后运行时解析报错

**排查**：
1. 确认上传脚本 `key_id` 用的是 `pub["key_id"]`（不是 `pub["key"]`）
2. 确认 cookie JSON 中没有空 `name` 条目（Playwright `add_cookies` 会报 "Cookie should have non-empty name"）
3. 确认 `sameSite` 字段已被移除（`no_restriction` 不是 Playwright 合法值）

### Q5：push `.github/workflows/` 报 403

**原因**：Token 缺少 `workflow` 权限。

**解决**：Token 需同时勾选 `repo` 和 `workflow` 两个 scope。

### Q6：Node.js 20 弃用警告

GitHub Actions 运行器提示 Node.js 20 将弃用，属正常告警，不影响当前功能；后续可升级工作流的 `actions/*` 版本。

### Q7：fork 仓库的工作流是灰色/禁用状态

Fork 后新工作流默认为 `disabled_fork`，需在 Actions 页面手动 **Enable**。

## 九、安全注意事项

1. **Token 吊销**：部署完成后，所有在对话/脚本中出现过的 GitHub Token 必须立即在 `Settings → Developer settings` 吊销或轮换（Actions 调度不依赖 Token）。
2. **cookies 属于敏感凭证**：等同账号登录态，不要提交到仓库、不要明文长期保存在本地；仅存于 GitHub Secret（加密存储）。
3. **本地清理**：上传 Secret 后删除本地明文 cookies 文件。
4. **cookies 有效期**：抖音登录态有有效期（本项目实测 `sid_guard` 约 2 个月，2026-08-22 → 2026-10-21）。到期后需重新导出并更新 Secret，否则会回到 Q1 的登录页问题。建议在日历中设置提醒。
